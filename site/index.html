About

画面の中に、置き物がある感覚

上のフィギュアは画像ではなく、ブラウザで動いている3Dモデルです。作るのに必要なのは、キャラクターの絵と、いくつかの生成サービスと、少しのプログラムだけです。

スマホはジャイロ

本体を傾けた方向から覗き込めます。iPhoneは最初に「傾けて見る」をタップして許可します。

PCはカーソル

カーソルの位置に合わせて、正面から左右・上下に視点が回り込みます。

重い端末は静止

描画が遅い端末や「視差効果を減らす」設定では、ダンスを止めた静止フィギュアに切り替わります。

Build log

作り方：9つの工程

実際にこのフィギュアを作った順番です。数字はこのモデルでの実測値です。

  1. 01

    キャラクターの元絵を作る

    Midjourneyで雰囲気の良いベースキャラクターを作ります。この段階では細かい制御より、顔立ちと服のデザインを決めることが目的です。

    • 服は体に沿うもの（トップス、ショートパンツ）が3D化・踊らせ方ともに安定します
    • 柄や配色はテクスチャなので自由に入れられます
    使ったものMidjourney
  2. 02

    3D化用のキャラシートを作る

    元絵をもとに、GPT系の画像生成で正面・左右・背面・真上・顔アップをそろえます。仕上がりを一番左右するのがこの工程です。

    • Aポーズで腕を45°ほど開き、手を体や服から離す
    • 遠近感のない正投影、影のないフラットな照明、台座なし
    枚数6枚（うち4枚を3D化に使用）
  3. 03

    複数のサービスで3D化して比べる

    同じキャラシートをTripoとHunyuan3Dに入れて比較しました。Tripoは左右で違うソックスや髪色まで忠実で、Hunyuan3Dは柄と髪色が変わりました。

    • どのサービスが合うかはキャラ次第なので、2社以上で試すのが確実です
    費用（Higgsfield経由）Tripo H3.1 複数視点 18cr
    Hunyuan3D v3 19cr
    出力約100万面 · 4Kテクスチャ · 67MB
  4. 04

    向きを直して軽くする

    横向きに出力されたモデルを正面に回転し、身長1.55mにそろえて、面数とテクスチャを減らします。骨入れサービスは大きすぎるデータを受け付けませんでした。

    • 32万面では骨入れが失敗し、10万面で成功
    軽量化100万面 → 10万面
    67MB → 7MB
    テクスチャ 4096 → 2048px
  5. 05

    骨とダンスを入れる

    Meshyの自動リギングで人型の骨（24本）を埋め込み、用意された約680種類の動きからダンスを選びます。

    • 今回は All_Night_Dance（約8秒のループ）
    費用骨入れ＋ダンス 8cr
  6. 06

    骨の割り当てを直す

    自動リギングは、手のそばにある服まで手の骨に付けてしまいます。メッシュのつながりと面の向きから「腕」と「体」を分け直し、脇の下だけはなめらかに伸びるように割り当て直しました。

    • スカートのキャラでは、裾に8本の補助の骨を足して太ももに合わせて持ち上げました
    処理Python（numpy / scipy）でglTFを直接書き換え
  7. 07

    ビューアを作る

    three.jsで描画し、スマホは傾きセンサー、PCはカーソル位置をカメラの向きにつなぎます。揺れは補間してなめらかにしています。

    • iPhoneのセンサーはHTTPSとタップでの許可が必須
    • 画面外に出たら描画を止めて電池を節約
    使ったものthree.js r147 · GLTFLoader
  8. 08

    色を合わせる

    生成されたテクスチャの鮮やかさはキャラシートと同じでしたが、照明が強すぎて白っぽく見えていました。金属感をゼロにし、環境光と露出を下げ、彩度を少し補正しています。

    設定metalness 0 · 環境光 0.55
    露出 0.8 · 彩度 +25%
  9. 09

    公開する

    GitHub Pagesで公開しています。傾きセンサーはHTTPSのページでしか動かないので、ファイルを置くだけでHTTPSになる無料の配信先が向いています。

    • 3Dモデルは圧縮して約4.9MB

Checklist

キャラシートで押さえること

3D化と骨入れの破綻の多くは、キャラシートの段階で防げます。

1

腕と体のあいだにすき間

腕を45°ほど開き、手を太ももや服から離します。くっついていると、手と服が一緒に動いて破れます。

2

台座なし・足裏は平ら

台座が一体になると、踊らせたときに一緒に変形します。

3

正投影・同じ縮尺

見上げや見下ろしにせず、全視点で頭と足の高さをそろえます。

4

影のないフラットな照明

強い陰影は模様としてテクスチャに焼き付きます。光沢は後から設定で付けます。

5

左右の違いを全視点で一致

左右で違うソックスなどは、「キャラ本人から見て右」を基準に統一します。

6

細い部品と文字は後付け

チェーンや細いベルトは崩れ、文字ロゴは読めなくなります。別に作って後から付けます。

傾きとカーソルをカメラにつなぐ

このページのファーストビューで使っている考え方です。視点は正面から左右35°・上下25°の範囲に絞っています。

// 傾き（スマホ）：最初の姿勢からの差だけを使う
addEventListener("deviceorientation", e => {
  if (base == null) base = { b: e.beta, g: e.gamma };
  target.yaw   = clamp((e.gamma - base.g) * 1.2, -35, 35);
  target.pitch = clamp((e.beta  - base.b) * 0.9, -10, 25);
});

// カーソル（PC）：画面中央からのずれを角度に
addEventListener("pointermove", e => {
  target.yaw   = (e.clientX / innerWidth  - 0.5) * 70;
  target.pitch = (e.clientY / innerHeight - 0.5) * 30;
});

// 毎フレーム、少しずつ近づけてなめらかに
view.yaw   += (target.yaw   - view.yaw)   * 0.08;
view.pitch += (target.pitch - view.pitch) * 0.08;

傾きの基準は、ゆっくり今の姿勢に追従させています。寝転んで見ても、机に置いて見ても、自然な角度が「正面」になります。

  • iPhoneは DeviceOrientationEvent.requestPermission() をタップの中で呼ぶ必要があります
  • 指の操作はページのスクロールに譲り、3D側では受け取りません
  • 最初は静止画を表示し、3Dの準備ができたら切り替えます
